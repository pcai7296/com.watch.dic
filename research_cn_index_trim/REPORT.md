# cn_index 降精度调研报告（方向1）

> 只读调研，未改动任何 app 代码 / 字典分片。
> 数据来源：`build/common/dict/cn_index`（96 个分桶文件，已部署产物）。
> 方法：复现生成器 `generate_watch_dict.py` 的 Phase1（ECDICT 派生）+ 解码 cn_index，把每条词条归类为「core / other」。

## 1. 现状

| 指标 | 值 |
|------|----|
| 总词条数 | 122,504 |
| 总体积（未压缩，含换行） | 1,721,220 B ≈ **1.64 MB** |
| 平均每词条字节 | 14.05 |
| 压缩后（前期测量） | ≈ 1.31 MB（占 rpk 字典 2.37MB 的大头） |

## 2. 词组来源归因（核心结论）

| 类别 | 词条数 | 字节 | 占比 |
|------|--------|------|------|
| **core**（ECDICT 英文词的中文释义，双语核心） | 37,291 | 494,748 | 28.7% |
| **other**（CC-CEDICT 增补的独立中文词条） | 85,213 | 1,226,472 | 71.3% |
| 合计 | 122,504 | 1,721,220 | 100% |

说明：生成器 Phase1 从 15k 英文词的 `translation` 抽取中文短语（37,291 条）；Phase2 用 CC-CEDICT 把 **97,750** 个独立中文词条反向挂到英文 entry，其中 12,537 与 core 重叠，故净增 85,213 条「other」。**ccedict-only 词条占 cn_index 体积的 71%**，是绝对大头。

## 3. 长度分布（按字符数，core / other）

| 长度 | 总 | core | other |
|------|----|------|-------|
| 2 | 58,478 | 13,483 | 44,995 |
| 3 | 29,538 | 11,073 | 18,465 |
| 4 | 22,896 | 6,245 | 16,651 |
| 5+ | 11,596 | 8,200 | 3,396 |

注意：**2 字词组里 77% 是 CC-CEDICT 增补**。即「other」不只是生僻长词，也包含大量日常双字词。

## 4. 降精度情景建模（保留字节 / 节省）

| 情景 | 保留字节 | 节省 | 节省比例 |
|------|----------|------|----------|
| **A 仅保留 core（丢 CC-CEDICT）** | 494,748 | 1,226,472 | **71.3%** |
| B 长度≤2 | 769,582 | 951,638 | 55.3% |
| B 长度≤3 | 1,129,188 | 592,032 | 34.4% |
| B 长度≤4 | 1,498,529 | 222,691 | 12.9% |
| C core 且长度≤4 | 390,507 | 1,330,713 | 77.3% |

## 5. 降低精度相对现在的后果

1. **影响范围有限且确定**：`cn_index` 仅服务于「中文输入 → 英文释义」的反向检索（results.ux:771 读取）。**英文 → 中文 的主路径（words / entries / zh_index）完全不经过 cn_index**，所以任何 cn_index 裁剪都**不会破坏主词典**，英文查词 100% 不受影响。
2. **唯一后果**：被裁掉的中文短语，在用户用中文输入法键入时无法直接命中英文释义（会落到 zh_index 单字或空结果）。
3. **情景 A（丢 CC-CEDICT）**：cn_index 从 1.64MB → 0.47MB，压缩后约 1.31MB → 0.38MB，**rpk 整体可省约 0.9MB**（从 2.72MB → ~1.8MB，仍远低于 4MB 普通包上限）。代价是中文输入可查词从 12.2 万降到 3.7 万，**丢失的 8.5 万词条里含 4.5 万日常双字词**——对「爱用中文查英文」的用户是明显退化。
4. **长度封顶（B）是弱杠杆**：即便只留 ≤4 字也仅省 13%，因为双/三字词组数量极多。单独用长度裁剪性价比低。
5. **无词频资源，无法做真正的「精度」裁剪**：`phrases.csv` 是英文短语表，CC-CEDICT 本身无词频。因此"降精度"只能按**来源**（丢 CC-CEDICT）或**长度**两个粗糙维度，无法按"常用/罕见"精细取舍。

## 6. 建议（待用户定方向，本研究不动代码）

- 若产品以**英文→中文**为主、中文输入是次要场景：**情景 A 是最高 ROI**——近 1MB 包体节省，主词典零影响。
- 若**中文输入很重要**：不要整段丢 CC-CEDICT，可考虑「core + 保留 CC-CEDICT 中 ≤3 字的高频双/三字」（情景 B≤3 保留 65.6% 体积、约 8.8 万词条），在包体与中文覆盖间折中；但节省仅 ~34%。
- 真正的"降精度不丢常用词"需要引入**中文词频表**（如 BNC/COCA 中文映射或 Subtlex）做保留白名单——当前数据不具备，属方向外新增工作。
